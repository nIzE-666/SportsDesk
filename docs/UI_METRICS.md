# Замеры интерфейса SportsDesk

Исходная точка («до») — коммит `07c7de5`. Текущее состояние («после») — коммит `b6e0d8c`: конец этапа U1 в ветке `sportsdesk/ui-refresh`, замер от 12 ноября 2026 года; прежние промежуточные значения коммита `0406d03` заменены. Оба замера выполнены одним сценарием Playwright на фиксированных тестовых ответах, с десятью избранными клубами, в окне 1440 × 900, классическом оформлении и тёмной теме. Это не те же данные, что в исходной оценке плана по реальным провайдерам.

Высота — `scrollHeight` корневого элемента экрана; кнопки и поля — отображаемые элементы внутри него, в том числе ниже области прокрутки; слова — количество частей `innerText`, разделённых пробелами. Высота области содержимого — 822 px. Сценарий ожидает появления экрана и 300 мс для отрисовки ответов. Числа зависят от тестового набора, а не описывают все возможные состояния.

- «Дневник» без записей: исчезли плитки с нулями и шесть фильтров (поля 6 → 0, высота 1086 → 404 px).

## Пользовательские сценарии

Каждый сценарий начинается с запуска футбольного обзора на фиксированную дату 22 октября 2026 года. Избран Arsenal; в данных есть вчерашний результат, следующий матч, календарь гонок и таблицы. Считаются явные нажатия, включая сохранение; прокрутка не считается. Проверены указанные маршруты, а не доказана их минимальность.

| Сценарий | До | После | Проверка результата |
|---|---:|---:|---|
| Счёт вчерашнего матча клуба | 0 | 0 | Счёт на главной |
| Следующий матч и следующая гонка | 1 | 1 | Матч на главной и гонка в календаре |
| Статистика конкретного матча | 2 | 2 | Показатели матча |
| Таблица лиги | 1 | 1 | Строка клуба |
| Зачёт пилотов | 2 | 2 | Строка пилота |
| Включить трансляцию текущего матча | — | — | Не измерено: нужен вход Kino и проверяемый эфир |
| Изменить уведомления одного клуба | 3 | 3 | Сохранённое изменение для клуба |
| Отметить матч просмотренным | 3 | 3 | Запись сохранена в дневнике |

После этапа U1 число нажатий не изменилось ни в одном сценарии: этап чистил экраны, а не маршруты. Дополнительно на тестовом завершённом матче переход к экрану просмотра занимает 2 нажатия, но это не подтверждает запуск прямой трансляции. Данные сценариев сохранены в `UI_SCENARIOS_BASELINE.json` и `UI_SCENARIOS_CURRENT.json` (после — коммит `b6e0d8c`; файл совпадает с прежним промежуточным значением). Пункт U0.3 остаётся частично проверенным до замера воспроизведения в подключённом приложении.

Повторный запуск в PowerShell из корня проекта:

```powershell
$env:SPORTSDESK_METRICS_OUTPUT = (Join-Path (Get-Location) 'docs/UI_METRICS_CURRENT.json')
npx playwright test e2e/uiMetrics.pw.ts
Remove-Item Env:SPORTSDESK_METRICS_OUTPUT
```

Сценарии действий: задайте `SPORTSDESK_SCENARIOS_OUTPUT` вместо `SPORTSDESK_METRICS_OUTPUT` и запустите `npx playwright test e2e/uiScenarios.pw.ts`. Если порт 1421 занят, задайте другой в `SPORTSDESK_E2E_PORT`.

Для исходного замера использовалось отдельное рабочее дерево коммита `07c7de5`, куда были временно скопированы только сценарий и фиксированные данные. Замер «после» выполнен в рабочем дереве ветки на коммите `b6e0d8c`, сценарии и данные взяты из самого коммита. При изменении сценария нужно повторить оба замера.

## Пояснительные тексты

Считаются видимые абзацы, подписи, пояснения и подсказки (`p`, `small`, `.muted`, `.settings-note`, `.eyebrow`, `summary`, `label` и элементы с `hint`, `note`, `lede` в классе) из шести слов и больше. Одинаковый текст на одном экране (для вкладок матча — в одном состоянии матча) считается один раз. Окно 1440 × 900, оформление «Спортивная обложка», тёмная тема, данные `e2e/uiFixture.ts`; для вкладок матча с подробностями к ним добавлены данные `e2e/matchDetails.ts`.

Замер сделан в двух областях.

- Узкая область — 29 состояний экранов: обзор, пять разделов футбола, клуб, шесть экранов Формулы-1, пять экранов Лиги чемпионов, четыре экрана кубков, планировщик, дневник, офлайн-сезоны, игры, просмотр, центр событий и настройки. Вкладки матча сюда не входят.
- Широкая область — те же 29 состояний и ещё: вкладки завершённого матча (три состояния), семь шагов мастера первого запуска и мини-окно.

| Состояние, 29 состояний экранов | Элементов | Слов в них |
|---|---:|---:|
| Основа `07c7de5` | 92 | 1293 |
| `908fb6d`, повторно `972e444` | 66 | 702 |
| `b6e0d8c` | 57 | 513 |

| Область широкого замера | `972e444` элементов / слов | `b6e0d8c` элементов / слов |

| Матч с оценками, событиями и ударами с xG (те же вкладки, профиль игрока, редактор схемы, форма записи о просмотре) | 34 / 459 | 23 / 220 |
| Матч, который ещё не начался | 10 / 105 | 5 / 35 |

| Итого | 148 / 1687 | 113 / 995 |

Что означают числа:

- Для 29 состояний с основы `07c7de5` элементов стало на 38% меньше (92 → 57), слов — на 60% (1293 → 513).
- Широкую область на `07c7de5` не измеряли: расширенного сценария тогда не было. Её основа — коммит `972e444`, до правок вкладок матча и мастера.
- Одинаковый текст в разных состояниях считается в каждом из них (например, подсказки вкладки «Мои схемы» есть во всех трёх состояниях матча), поэтому «Итого» — сумма по областям, а не число разных текстов.
- Мини-окно на тестовых данных показывает только короткое сообщение об ошибке, без пояснения, поэтому 0. Пустое состояние и список матчей мини-окна не измерены.
- В «Настройках» остаётся 30 из 57 элементов (272 слова из 513). Часть из них счётчик принимает за пояснения, хотя это подписи выбора с перечнем вариантов («Движение: Как в системе, Спокойно, …»).
- Цифра плана «237 элементов в 46 файлах» получена другим способом (подсчёт в разметке); способ не записан и не воспроизводится, поэтому прямо сравнивать с ней нельзя. Цель «не больше 80» из раздела 7 плана в этом замере соответствует примерно 31 элементу при той же доле сокращения (80 из 237), точное значение цели нужно подтвердить. Сейчас в узкой области 57: цель по этой доле пока не достигнута.

Повторный запуск в PowerShell из корня проекта; список текстов записывается в указанный файл, после списка идёт сводка «ПО ОБЛАСТЯМ», последняя строка содержит итог по всем областям:

$env:SPORTSDESK_TEXT_OUTPUT = (Join-Path $env:TEMP 'ui-text-audit.txt')
