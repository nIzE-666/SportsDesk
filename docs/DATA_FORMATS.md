# Форматы пользовательских данных SportsDesk

Этот документ описывает версии всех форматов, которые переживают обновление
приложения или переносятся между компьютерами. Любое изменение формата
сопровождается повышением версии, миграцией старой версии и тестом, который
восстанавливает данные старого формата в новом приложении.

## Сводка

## Профиль настроек (v1)

```json
{
  "app": "SportsDesk",
  "version": 1,
  "exportedAt": "…",
  "settings": { "sportsdesk.scheme": "dark" }
}
```

- В профиль попадают только ключи из разрешённого списка (`is_allowed_key`).
  Ключи с `token`, `secret`, `api_key`, `password`, `credential` отклоняются.
- Ограничения: не больше 200 ключей, ключ ≤ 128 байт, значение ≤ 200 000 байт,
  весь профиль ≤ 1,5 МБ.
- Новый переносимый ключ добавляется в разрешённый список; версия профиля при
  этом не меняется.
- `sportsdesk.sidebar.competitionsOpen` и `sportsdesk.sidebar.teamsOpen` сохраняют
  раскрытие списков бокового меню: `0` — свёрнут, `1` — раскрыт. При отсутствии
  ключа список раскрыт.
- Переименование или изменение смысла существующего ключа требует `version: 2`
  и миграции v1 → v2 при чтении.

## Тактические схемы (v1)

- Один ключ `sportsdesk.football.tactics`, включённый в профиль и полную резервную копию.
  Отсутствие ключа в старом профиле означает пустую библиотеку; версия профиля остаётся 1.
- Объект `{ version: 1, schemes: [...] }`: до 20 именованных схем, всё значение не больше
  190 000 байт UTF-8. При заполнении новая запись отклоняется; старые не удаляются автоматически.
- Схема привязана к ID матча или одной из команд исходного матча. В ней сохраняются
  снимок команд, статус подтверждения состава, игроки, исходные/личные позиции и стрелки.
- Позиции и концы стрелок — конечные числа в диапазоне 0–1. До 80 игроков и 80 стрелок
  на схему. Игрок определяется парой ID команды и ID игрока; ID схем и стрелок уникальны.
- Исходные позиции отделены от редактируемых. Восстановление проверяет весь формат
  до применения настроек. Более новая версия требует обновить приложение; повреждённые
  данные не перезаписываются при обычном сохранении новой схемы.
- Незаконченная доска хранится в состоянии текущей сессии и не входит в резервную копию.
  Чтобы перенести её, пользователь сохраняет именованную схему.

## Дневник просмотра (v1)

- Один ключ `sportsdesk.view.diary` входит в профиль и полную резервную копию.
  В старом профиле без ключа дневник пустой; версия профиля остаётся 1.
- Экспорт JSON имеет тот же формат `{ version: 1, entries: [...] }`. Экспортируется
  компактный JSON, поэтому файл дневника в пределах лимита можно импортировать обратно.
- До 500 записей и 190 000 байт UTF-8 на весь дневник. Заполнение отклоняет запись
  или импорт целиком, без удаления старых заметок. Пользователь может экспортировать
  данные перед явным удалением ненужного.
- Запись содержит снимок события (спорт, название, сезон, дата, необязательная ссылка
  на ID матча или сезон/раунд гонки F1), дату просмотра, заметку до 1500 символов,
  до 8 тегов по 30 символов, личную оценку 1–10 либо `null`, время создания и изменения.
- Дата просмотра — календарный день `YYYY-MM-DD`; значение по умолчанию берётся в
  часовом поясе пользователя. Отсутствие оценки не заменяется нулём.
- Одна связанная запись определяется ID матча или парой сезон/раунд F1. Для ручной
  записи без источника используется `manual:<UUID>`. Исправления данных источника
  не обновляют личные снимки, заметки и оценки автоматически.
- Импорт сначала проверяет весь файл и показывает количество новых/совпадающих записей.
  Совпадения сохраняют текущие данные; замена включается отдельным явным выбором.
  При повреждённом или более новом формате профиль не меняется.
- Дневник живёт вне `cache.sqlite3`; очистка старых строк `api_cache` на него не влияет.
  Журнал прогнозов хранится отдельно: дневник только читает связь по ID матча.
- Названия, теги, заметки, оценки и итоги прогнозов скрытого события закрываются режимом
  без спойлеров; скрытые записи исключены из таблицы сезонов и среднего рейтинга.
  Явный экспорт содержит все личные записи, в том числе скрытые.

## Полная резервная копия (v2)

```json
{
  "app": "SportsDesk",
  "version": 2,
  "profile": { "…": "профиль v1" },
  "historySqlite": "<base64 снимка SQLite>",
  "historySha256": "<hex>"
}
```

- Версия 1 — это просто файл профиля; при восстановлении история не меняется.
- Снимок истории проверяется до любых изменений: SHA-256, `PRAGMA quick_check`,
  отсутствие лишних таблиц, триггеров и представлений, версия схемы.
  Из снимка копируются только строки; SQL из файла не выполняется.
- Копии и профили более новой версии отклоняются с сообщением «Копия создана
  более новой версией SportsDesk. Обновите приложение…». Данные не меняются.

## База истории (схема v2)

- Таблица `history_matches` с первичным ключом `(league_id, season, id)`.
- Базы и снимки без отметки (`user_version = 0`) созданы до версионирования и
  имеют прежнюю структуру `history_matches`. При открытии v0/v1 транзакционно добавляется
  `offline_seasons`, сохраняются все строки истории и ставится `user_version = 2`.
- Снимки v0/v1 восстанавливаются как история без пакетов; v2 переносит обе таблицы
  и закрепления атомарно. Повреждённый или более новый пакет отклоняет восстановление
  до изменения живой базы. Версия схемы новее поддержанной запрещает открытие до записи.
- Новая миграция: увеличить `HISTORY_SCHEMA_VERSION`, добавить шаг в
  `History::open` (в транзакции, от меньшей версии к большей), научить
  `read_snapshot` читать старые снимки и добавить тест восстановления копии со
  старой схемой.

## Офлайн-сезоны и очередь (v1)

- Нативный пакет хранится в `offline_seasons(league_id, season, payload)` с первичным
  ключом `(league_id, season)`. `payload`: `version: 1`, `leagueId`, `leagueName`,
  `season`, `fetchedAt` (момент ответа источника), `pinned`, число объединённых
  одинаковых дублей `duplicates` и массив `matches`. Матч содержит ID и имена команд,
  nullable-счёт, нормализованный статус, календарную дату, nullable-точное время UTC
  и тур. Изображения, трансляции, события и подробная статистика не входят.
- До 60 пакетов, 2000 матчей и 2 000 000 байт UTF-8 JSON каждый. Дубликаты ID,
  несовместимые версии, неверные даты и счёт отклоняются целиком. Обновление пакета
  и upsert аналитической истории идут в одной транзакции. История сохраняет прежние
  дополнительные строки; пакет представляет последний успешно проверенный ответ.
- Полнота вычисляется из пакета: проверены форматы пяти европейских лиг для
  2021/22–2026/27, ожидаемое число команд, все направленные пары дома/в гостях,
  количество матчей и наличие календарных дат. Неизвестный формат (в том числе MLS)
  получает «Полнота не проверена». Полный календарь не означает наличие будущих
  результатов или окончательно утверждённого времени; счёт и время учитываются отдельно.
- Пакеты не имеют TTL и не вытесняются автоматически. Закрепление запрещает удаление
  на уровне команды, пока его явно не снимут. Удаление пакета сохраняет историю,
  дневник и тактические схемы. `api_cache` — другая база; её очистка пакеты не меняет.
- Полная копия v2 переносит пакеты и закрепления вместе с историей; профиль переносит
  только очередь. Прежний общий предел снимка истории 64 МиБ / файла копии 96 МиБ
  сохраняется: при превышении создание копии выдаёт ошибку и не удаляет данные.
- Очередь: ключ `sportsdesk.view.offline`, `{version:1, paused, jobs}`. До 60 заданий
  и 100 000 байт UTF-8; одно задание на пару лига/сезон. Состояния: `queued`,
  `downloading`, `saving`, `done`, `error`; `attempt` отличает повторную попытку, `pin` хранит явное намерение закрепить
  пакет; обычное обновление сохраняет прежнее закрепление.
  Загружается один сезон за раз независимо от открытой страницы. После запуска
  прерванные задания возвращаются в очередь, вся очередь ставится на паузу.
  Продолжение явное; повтор записи после аварии идемпотентен. Пауза не прерывает
  начатую транзакцию. Ответ, пришедший на паузе до сохранения, не записывается.
- Устаревший кеш, пустой/неверный ответ и ошибка диска не заменяют прежний пакет.
  Повреждённая или будущая очередь доступна только для чтения; пакеты остаются доступны.
- Браузерный dev-мост мигрирует прежний массив `history.json` в
  `{version:2, rows, packages}` при первой записи; файл заменяется атомарно.
  Dev-база отдельна от нативной и не является полной резервной копией приложения.
- Аудит реальных данных: `docs/OFFLINE_SEASONS_DATA.md`.

## Журнал восстановления (v1)

- Пишется до изменения зеркала профиля и истории. Стадии: `committing`,
  `committed`, `rolled_back`.
- При запуске незавершённое восстановление доводится до конца из исходной копии
  или откатывается из защитной копии. Повреждённый журнал переименовывается в
  `restore-journal.corrupt-<ms>.json`.
- Пока журнал открыт, новые копии и запись зеркала профиля заблокированы.

## Секреты

Секреты привязаны к пользователю Windows через DPAPI и никогда не попадают в
профиль и резервные копии. После переноса на другой компьютер их нужно ввести
заново.

## Восстановление «Пока вас не было» (кеш, не входит в резервную копию)

Таблицы в `cache.sqlite`, которые не очищаются вместе с кешем API:

- `sync_cursor(source TEXT PRIMARY KEY, covered_until INTEGER, updated_at INTEGER)` — до какого момента (мс UTC) источник `football` или `f1` гарантированно проверен. Курсор продвигается только после того, как все ответы окна получены свежими и все записи в центр событий прошли успешно.
- `catchup_summary(id = 1, payload TEXT, updated_at INTEGER)` — одна сводка в JSON:
  `{ from, to, truncated, footballIncomplete, f1Incomplete, items: Event[] }` (до 60 событий, новые сверху). Удаляется кнопкой «Скрыть».

Правила: окно не длиннее 72 часов (`truncated = true`, если отсутствие было дольше), первый запуск и разрывы короче 20 минут ничего не восстанавливают, идентификаторы совпадают с событиями живого поллера (`football|end|<id>`, `f1|result|<season>|<round>|<session>`), поэтому дубли не создаются. Восстановленные события не вызывают уведомлений, звуков и конфетти. Авторы голов не восстанавливаются.

## Мастер первого запуска

Ключ `sportsdesk.onboarding` (входит в профиль и резервные копии):

```json
{
  "version": 1,
  "status": "in_progress",
  "step": "timezone",
  "origin": "new",
  "updatedAt": "2026-11-09T07:00:00.000Z"
}
```

- `status`: `in_progress` — мастер продолжится с `step` при следующем запуске; `completed` и `skipped` — больше не показывается сам.
- `step`: `welcome`, `football`, `f1`, `timezone`, `notifications`, `appearance`, `sources`.
- `origin`: `new` — новая установка, `existing` — обновление, `manual` — открыт из «Настроек».

Решение принимается один раз при загрузке модуля, до того как экраны запишут свои значения по умолчанию. Если ключа нет, но есть любой другой ключ `sportsdesk.*`, это обновление: записывается `completed`/`existing`, мастер не показывается и ничего не меняет. Мастер пишет только существующие ключи (`sportsdesk.league`, `sportsdesk.f1.favTeams`, `sportsdesk.f1.favDrivers`, `sportsdesk.timezone`, `sportsdesk.notifications.enabled`, `sportsdesk.notifications.f1`, `sportsdesk.scheme`, `sportsdesk.design`) и только при явном выборе. Разрешение на уведомления запрашивается лишь при включении. Новой установке окно «Что нового» не показывается.

## Избранные клубы и игроки (редактор)

Хранилище: `src/features/football/favoritesStore.ts`. Все экраны (матчи, планировщик, ЛЧ,
настройки, мастер первого запуска) читают одно состояние через `useSyncExternalStore`;
снимок пересобирается, только когда меняется сохранённая строка, поэтому экраны не
перезаписывают изменения друг друга.

- `sportsdesk.football.favorites.teams` — `{ ids: string[], dismissed?: string[], seeded?: string[], seededDefault?: boolean }`.
  - `ids` — id клубов в источнике. Это основная идентичность; названия и алиасы нужны только для поиска.
  - `dismissed` — нормализованные имена клубов по умолчанию, которые пользователь убрал. Они не возвращаются автоматически, только кнопкой «Вернуть».
  - `seeded` — клубы по умолчанию, уже сопоставленные с id каталога.
- `sportsdesk.football.favorites.players` — массив `FavoritePlayer`.
- `sportsdesk.football.catalogue` — `{ id, name, leagueName?, leagueId? }[]`, пополняется при открытии лиг; по нему работает поиск в редакторе.

Каждое изменение клубов отправляет `sportsdesk-favorites-changed`, и фоновый опрос на Rust сразу
получает новый список. Редактор («Настройки → Избранное», компактно — в шаге «Футбол» мастера)
показывает лигу рядом с названием, чтобы молодёжные и женские составы не путались, и не меняет
официальные данные источника.

## Расположение блоков главной

Ключ `sportsdesk.view.home.layout` (входит в резервную копию профиля через префикс `view.`).

```json
{ "version": 1, "order": ["clubs", "insights", "calendar", "editorial"], "hidden": ["calendar"] }
```

- `order` — порядок блоков футбольной главной; `null` означает стандартный порядок текущего оформления (классическое и «Трансляция» имеют разные стандартные порядки).
- `hidden` — скрытые блоки.
- Идентификаторы: `insights` (сводка), `calendar` (экспорт в .ics), `clubs` (ваши клубы), `editorial` (расписание и колонка избранного).
- Неизвестные и повторные идентификаторы отбрасываются; блоки, которых нет в сохранённом порядке, добавляются в конец. Более новые версии читаются по известным полям.
- Повреждённое значение (не JSON-объект или без числового `version` ≥ 1) отклоняется при восстановлении профиля; при чтении в приложении используется стандартное расположение.
- Блоки берут данные из общего `useFootballData` и не создают собственных запросов.

## Режим без спойлеров (v1)

Ключ `sportsdesk.view.spoilers` (входит в резервную копию профиля, проверяется при восстановлении).

```json
{
  "version": 1,
  "items": [
    {
      "kind": "football",
      "id": "<match id>",
      "label": "Арсенал — Челси",
      "eventTime": "2026-11-09T12:00:00Z",
      "addedAt": "2026-11-09T10:00:00Z"
    }
  ]
}
```

- `kind`: `football` или `f1`; пара `kind` + `id` уникальна, дубликаты и битые записи отбрасываются.
- Запись истекает через 7 дней после `eventTime` (или `addedAt`, если времени события нет).
- Скрытые id футбольных матчей передаются в Rust-поллер как `hiddenResults`: для них не создаются уведомления о голах и итогах и записи Центра событий (напоминания «Скоро матч» остаются).
- Маска счёта: `? : ?`. Скрыто в карточках и списках матчей, на главной, в карточке матча (события, статистика, оценки), мини-окне, Центре событий и «Пока вас не было».
- Этап Формулы-1 помечается записью `kind: "f1"` с `id` вида `<сезон>|<этап>` (например, `2026|21`, функция `f1SpoilerId`). Она скрывает итоги этого этапа в Центре событий, «Пока вас не было» и не даёт показать клетчатый флаг и подиум. Кнопки для скрытия этапа Формулы-1 в интерфейсе пока нет, а экраны F1 (итоги, зачёт) эту запись ещё не учитывают.

## Игры и атмосфера (v1)

Ключ `sportsdesk.view.atmosphere` (входит в резервную копию профиля, проверяется при восстановлении).

```json
{
  "version": 1,
  "enabled": true,
  "celebrations": true,
  "sounds": false,
  "ambient": false,
  "volume": 0.5,
  "motion": "system",
  "ambientKind": "auto",
  "ambientVolume": 0.4,
  "ambientVideo": "stop",
  "ambientHidden": "stop"
}
```

- `enabled` — главный выключатель блока; `celebrations` — конфетти гола и флаг финиша; `sounds` и `ambient` по умолчанию выключены и не включаются сами после обновления.
- `motion`: `system` (как в Windows), `reduced` (без частиц и тряски), `full`.
- `volume` — от 0 до 1, громкость коротких сигналов (рог гола, радио F1); значения вне диапазона обрезаются.
- Поля фонового звука добавлены без смены версии: в старых профилях их нет, при чтении берутся значения по умолчанию, неизвестные значения заменяются ими же, более старое приложение лишние поля игнорирует.
  - `ambient` — разрешает кнопку «Фоновый звук» в верхней панели. Сам фон включается только этой кнопкой (или «Прослушать фон» в настройках) и не запоминается как «играет»: после запуска и обновления он всегда выключен.
  - `ambientKind`: `auto` (стадион в футболе, кубках и ЛЧ, двигатель в Формуле 1), `stadium`, `engine`. При смене вида спорта или значения звук плавно переключается.
  - `ambientVolume` — отдельная громкость фона от 0 до 1 (на слух ограничена запасом 0,5).
  - `ambientVideo`: `stop` — фон выключается, пока видео в «Онлайн-просмотре» звучит (запускать его заново нужно вручную); `lower` — фон тише в 5 раз и возвращается после паузы или выключения звука видео.
  - `ambientHidden`: `stop` — фон выключается, когда окно скрыто в трей или свёрнуто, и сам не возвращается; `keep` — продолжает звучать. Rust присылает событие `sportsdesk://window-visibility`, потому что WebView2 не всегда считает скрытое в трей окно скрытым.
- Фоновые звуки и сигналы синтезируются самим приложением (Web Audio), готовых записей и сторонних файлов нет. Фон не привязан к ходу матча или гонки, поэтому не может раскрыть результат. Тихие часы уведомлений не звучат для автоматических сигналов; фон, включённый вручную, они не прерывают. Сигналы не звучат поверх видео со звуком и из скрытого окна.

Ключ `sportsdesk.view.celebrated` — массив id событий Центра событий, для которых праздник уже показан (не больше 300). Не даёт повторить праздник после перерендера, обновления данных и перезапуска. Празднуются только события `football|goal|…` не старше 10 минут; изменение счёта без события гола (исправление, отмена) не празднуется.

## Командное радио F1

- `sportsdesk.notifications.f1.radio` — `"1"` включает оформление напоминаний о сессиях F1 как радиосообщений SportsDesk (по умолчанию выключено и работает только при включённом блоке «Игры и атмосфера»).
- `sportsdesk.notifications.f1.radioName` — обращение в репликах (до 24 символов, управляющие символы удаляются).
- В Rust уходят поля `f1Radio` и `f1RadioName` конфигурации опроса. Ключ напоминания не меняется, поэтому оформление не создаёт дублей; фильтры и тихие часы применяются как обычно. День недели («гоночная пятница») считается по времени начала сессии в часовом поясе пользователя. Реплики не объявляют пит-стопы и не выдаются за настоящие записи команд.

## Клетчатый флаг и подиум

Праздник после финиша гонки или спринта Формулы-1. Новых пользовательских данных нет: показанные подиумы запоминаются в уже существующем ключе `sportsdesk.view.celebrated` (id события вида `f1|result|<сезон>|<этап>|race` или `…|sprint`, вместе с голами не больше 300).

- Источник — Rust-наблюдатель `f1_finish.rs`. Он спрашивает итоги у Jolpica через общий кеш моста (`<сезон>/<этап>/results.json` или `sprint.json`), только пока включена лента F1 (`f1Reminders`): гонку — от 1 до 12 часов после старта по расписанию, спринт — от 30 минут до 6 часов, раз в 3 минуты. Квалификации флага не получают. Пустой ответ Jolpica (итогов ещё нет) кешируется 2 минуты, а не 15.
- Финиш подтверждается только опубликованными итогами: должны быть классифицированные пилоты на местах 1, 2 и 3 (`position` совпадает с `positionText`). Расписание задаёт лишь окно запросов; победитель не выбирается по расписанию или текущему лидеру. Нет итогов или подиум неполный — ничего не происходит.
- Праздник «живой» только если наблюдатель сам видел сессию без итогов не более 20 минут назад. После запуска приложения, сна или долгого сбоя сети итоги записываются в Центр событий молча, событие `sportsdesk://f1-finish` не отправляется. Событие Центра событий то же (`f1|result|…`), что у «Пока вас не было»: `INSERT OR IGNORE` не даёт ни дублей, ни повторного праздника после исправления итогов и перезапуска. Если запись уже сделала догрузка, праздника нет.
- Событие `sportsdesk://f1-finish` несёт `{ id, season, round, session, label, raceName, podium: [{ position, driver, team, constructorId }] }` (ровно три места). Интерфейс проверяет форму и отбрасывает всё лишнее, спрашивает `celebrations` и тихий режим окна, режим без спойлеров (`2026|21` выше) и список показанного. Выключенные празднования и скрытое окно подиум не показывают, но помечают как показанный: позже он не всплывёт.
- Подпись всегда «по опубликованным итогам Jolpica; возможны поправки после решений стюардов»: источник не отличает предварительную классификацию от окончательной. Исправленные итоги подиум не повторяют.
- При уменьшенном движении — статичная карточка без флага и брызг. Звука у флага нет.

## Игра «Стартовые огни» (v1)

Раздел «Игры» (пункт в боковой панели, пока включён блок «Игры и атмосфера») открывается только действием пользователя; игра загружается отдельным модулем при открытии. Личная статистика — ключ `sportsdesk.view.games.startLights` (входит в резервную копию профиля, проверяется при восстановлении).

```json
{
  "version": 1,
  "rounds": 14,
  "falseStarts": 2,
  "best": { "ms": 214, "at": "2026-11-09T12:00:00.000Z" },
  "history": [{ "ms": 231, "at": "2026-11-09T12:00:00.000Z" }]
}
```

- `rounds` — завершённые попытки: со временем, фальстартом или «не успели». Прерванные (потеря фокуса, скрытое окно, уход с экрана) не считаются и ничего не пишут.
- `history` — не больше 20 последних попыток со временем, новые в конце; `best` хранится отдельно и не пропадает, когда рекорд выпал из истории. Время — целые миллисекунды от 100 до 2000, остальные записи отбрасываются при чтении. Неизвестная более новая версия читается по известным полям.
- Правила: огни зажигаются по одному каждые 0,8 с, после пятого гаснут через случайное время 0,2–3 с. Время считается монотонными часами (`performance.now()`, момент нажатия — `event.timeStamp`) от кадра, в котором огни погасли на экране. Нажатие до этого кадра или раньше 0,1 с после него — фальстарт (угадывание); без нажатия за 2 с попытка заканчивается без времени. Удержание клавиши (`repeat`) не засчитывается; после результата 0,6 с новая попытка не начинается от случайных нажатий.
- Время включает задержки экрана, мыши или клавиатуры и системы. В игре нет сравнений с реакцией настоящих пилотов; «игровая цель» в 250 мс — просто ориентир для игрока. Предгоночной заставки по расписанию пока нет.

## Игра «Угадай счёт» (v1)

Вкладка «Угадай счёт» в разделе «Игры» и панель «мой прогноз» в карточке матча. Данные — ключ `sportsdesk.view.games.predictions` (входит в резервную копию профиля, проверяется при восстановлении).

```json
{
  "version": 1,
  "items": [
    {
      "matchId": "…",
      "leagueId": "l_4WFCIZ",
      "home": 2,
      "away": 1,
      "homeTeam": "Arsenal",
      "awayTeam": "Chelsea",
      "kickoff": "2026-11-09T17:30:00.000Z",
      "createdAt": "…",
      "updatedAt": "…",
      "rules": 1,
      "result": { "home": 2, "away": 1, "seenAt": "…" },
      "void": "cancelled"
    }
  ]
}
```

- Угадывается счёт ОСНОВНОГО времени. Источник отдаёт только итоговый счёт и статус, поэтому прогнозы принимаются только в Premier League, Ла Лиге, Серии A, Бундеслиге и Лиге 1 (там нет дополнительного времени). Кубки, Лига чемпионов и MLS (плей-офф с дополнительным временем) не входят. Если источник пометил матч как дошедший до дополнительного времени или пенальти (`AET`, `After penalties` и т. п.), в запись ставится `void: "extra-time"`, итог не сохраняется, очки не начисляются.
- Очки не хранятся: они выводятся из прогноза и последнего известного итога (`result`) по таблице правил версии `rules`. Версия `1`: 3 очка за точный счёт, 1 за верный исход, иначе 0. Новые правила получают новый номер, старые прогнозы считаются по своей версии, поэтому прежняя статистика не меняется. Повторный расчёт не удваивает очки, исправленный итог заменяет прежний и пересчитывает запись.
- Прогноз принимается и меняется, пока матч `scheduled` и его начало (`time_utc`) известно и ещё не наступило. Без известного времени начала прогноз не принимается; начавшийся, завершённый, отменённый и перенесённый матч закрывают редактирование. Перенос обновляет `kickoff` (и прогноз остаётся), отмена ставит `void: "cancelled"` (пометка снимается, если матч вернулся в расписание). Прогноз, изменённый не раньше начала матча, не засчитывается.
- Итоги подхватываются, когда пользователь открывает матч или нажимает «Проверить результаты» во вкладке (только свежие ответы источника, не устаревшие). Рассчитанный прогноз убрать нельзя, ожидающий до начала матча — можно.
- Матчи, скрытые режимом без спойлеров, не раскрывают счёт и очки и не входят в итоги, пока результат не показан. Это личные данные: «Очистить кеш» их не стирает.
- Модель прогнозов приложения (пункт 1 плана) будет показываться отдельно от этих ручных прогнозов.
