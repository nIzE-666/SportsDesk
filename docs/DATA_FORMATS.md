# Форматы пользовательских данных SportsDesk

Этот документ описывает версии всех форматов, которые переживают обновление
приложения или переносятся между компьютерами. Любое изменение формата
сопровождается повышением версии, миграцией старой версии и тестом, который
восстанавливает данные старого формата в новом приложении.

## Сводка

| Формат                   | Где живёт                              | Текущая версия            | Читается              | Код                        |
| ------------------------ | -------------------------------------- | ------------------------- | --------------------- | -------------------------- |
| Профиль настроек         | `profile-mirror.json`, экспорт `.json` | `version: 1`              | 1                     | `src-tauri/src/profile.rs` |
| Полная резервная копия   | `*.sdbackup.json`                      | `version: 2`              | 1 (только профиль), 2 | `src-tauri/src/backup.rs`  |
| База истории матчей      | `history.sqlite3`                      | `PRAGMA user_version = 1` | 0, 1                  | `src-tauri/src/history.rs` |
| Журнал восстановления    | `restore-journal.json`                 | `version: 1`              | 1                     | `src-tauri/src/backup.rs`  |
| Секреты (PitchAPI, Kino) | `secrets\\*.dpapi`                     | —                         | —                     | `src-tauri/src/secrets.rs` |

## Профиль настроек (v1)

```json
{
  "app": "SportsDesk",
  "version": 1,
  "exportedAt": "…",
  "settings": { "sportsdesk.scheme": "dark" }
}
```

- В профиль попадают только ключи из разрешённого списка (`is_allowed_key`).
  Ключи с `token`, `secret`, `api_key`, `password`, `credential` отклоняются.
- Ограничения: не больше 200 ключей, ключ ≤ 128 байт, значение ≤ 200 000 байт,
  весь профиль ≤ 1,5 МБ.
- Новый переносимый ключ добавляется в разрешённый список; версия профиля при
  этом не меняется.
- Переименование или изменение смысла существующего ключа требует `version: 2`
  и миграции v1 → v2 при чтении.

## Полная резервная копия (v2)

```json
{
  "app": "SportsDesk",
  "version": 2,
  "profile": { "…": "профиль v1" },
  "historySqlite": "<base64 снимка SQLite>",
  "historySha256": "<hex>"
}
```

- Версия 1 — это просто файл профиля; при восстановлении история не меняется.
- Снимок истории проверяется до любых изменений: SHA-256, `PRAGMA quick_check`,
  отсутствие лишних таблиц, триггеров и представлений, версия схемы.
  Из снимка копируются только строки; SQL из файла не выполняется.
- Копии и профили более новой версии отклоняются с сообщением «Копия создана
  более новой версией SportsDesk. Обновите приложение…». Данные не меняются.

## База истории (схема v1)

- Таблица `history_matches` с первичным ключом `(league_id, season, id)`.
- Базы и снимки без отметки (`user_version = 0`) созданы до версионирования и
  имеют ту же структуру; при открытии база получает `user_version = 1`.
- Новая миграция: увеличить `HISTORY_SCHEMA_VERSION`, добавить шаг в
  `History::open` (в транзакции, от меньшей версии к большей), научить
  `read_snapshot` читать старые снимки и добавить тест восстановления копии со
  старой схемой.

## Журнал восстановления (v1)

- Пишется до изменения зеркала профиля и истории. Стадии: `committing`,
  `committed`, `rolled_back`.
- При запуске незавершённое восстановление доводится до конца из исходной копии
  или откатывается из защитной копии. Повреждённый журнал переименовывается в
  `restore-journal.corrupt-<ms>.json`.
- Пока журнал открыт, новые копии и запись зеркала профиля заблокированы.

## Секреты

Секреты привязаны к пользователю Windows через DPAPI и никогда не попадают в
профиль и резервные копии. После переноса на другой компьютер их нужно ввести
заново.

## Проверка совместимости

Тесты, которые должны оставаться зелёными:

- `backup::tests::rotation_keeps_seven_and_legacy_profile_is_supported` — копия v1;
- `backup::tests::history_snapshot_from_an_older_app_restores_and_newer_schema_is_refused`;
- `backup::tests::newer_backup_formats_are_refused_with_an_update_hint`;
- `backup::tests::crash_*` — восстановление после аварийного завершения;
- `history::tests::open_stamps_the_schema_version`.

## Восстановление «Пока вас не было» (кеш, не входит в резервную копию)

Таблицы в `cache.sqlite`, которые не очищаются вместе с кешем API:

- `sync_cursor(source TEXT PRIMARY KEY, covered_until INTEGER, updated_at INTEGER)` — до какого момента (мс UTC) источник `football` или `f1` гарантированно проверен. Курсор продвигается только после того, как все ответы окна получены свежими и все записи в центр событий прошли успешно.
- `catchup_summary(id = 1, payload TEXT, updated_at INTEGER)` — одна сводка в JSON:
  `{ from, to, truncated, footballIncomplete, f1Incomplete, items: Event[] }` (до 60 событий, новые сверху). Удаляется кнопкой «Скрыть».

Правила: окно не длиннее 72 часов (`truncated = true`, если отсутствие было дольше), первый запуск и разрывы короче 20 минут ничего не восстанавливают, идентификаторы совпадают с событиями живого поллера (`football|end|<id>`, `f1|result|<season>|<round>|<session>`), поэтому дубли не создаются. Восстановленные события не вызывают уведомлений, звуков и конфетти. Авторы голов не восстанавливаются.

## Мастер первого запуска

Ключ `sportsdesk.onboarding` (входит в профиль и резервные копии):

```json
{
  "version": 1,
  "status": "in_progress",
  "step": "timezone",
  "origin": "new",
  "updatedAt": "2026-11-09T07:00:00.000Z"
}
```

- `status`: `in_progress` — мастер продолжится с `step` при следующем запуске; `completed` и `skipped` — больше не показывается сам.
- `step`: `welcome`, `football`, `f1`, `timezone`, `notifications`, `appearance`, `sources`.
- `origin`: `new` — новая установка, `existing` — обновление, `manual` — открыт из «Настроек».

Решение принимается один раз при загрузке модуля, до того как экраны запишут свои значения по умолчанию. Если ключа нет, но есть любой другой ключ `sportsdesk.*`, это обновление: записывается `completed`/`existing`, мастер не показывается и ничего не меняет. Мастер пишет только существующие ключи (`sportsdesk.league`, `sportsdesk.f1.favTeams`, `sportsdesk.f1.favDrivers`, `sportsdesk.timezone`, `sportsdesk.notifications.enabled`, `sportsdesk.notifications.f1`, `sportsdesk.scheme`, `sportsdesk.design`) и только при явном выборе. Разрешение на уведомления запрашивается лишь при включении. Новой установке окно «Что нового» не показывается.

## Избранные клубы и игроки (редактор)

Хранилище: `src/features/football/favoritesStore.ts`. Все экраны (матчи, планировщик, ЛЧ,
настройки, мастер первого запуска) читают одно состояние через `useSyncExternalStore`;
снимок пересобирается, только когда меняется сохранённая строка, поэтому экраны не
перезаписывают изменения друг друга.

- `sportsdesk.football.favorites.teams` — `{ ids: string[], dismissed?: string[], seeded?: string[], seededDefault?: boolean }`.
  - `ids` — id клубов в источнике. Это основная идентичность; названия и алиасы нужны только для поиска.
  - `dismissed` — нормализованные имена клубов по умолчанию, которые пользователь убрал. Они не возвращаются автоматически, только кнопкой «Вернуть».
  - `seeded` — клубы по умолчанию, уже сопоставленные с id каталога.
- `sportsdesk.football.favorites.players` — массив `FavoritePlayer`.
- `sportsdesk.football.catalogue` — `{ id, name, leagueName?, leagueId? }[]`, пополняется при открытии лиг; по нему работает поиск в редакторе.

Каждое изменение клубов отправляет `sportsdesk-favorites-changed`, и фоновый опрос на Rust сразу
получает новый список. Редактор («Настройки → Избранное», компактно — в шаге «Футбол» мастера)
показывает лигу рядом с названием, чтобы молодёжные и женские составы не путались, и не меняет
официальные данные источника.

## Расположение блоков главной

Ключ `sportsdesk.view.home.layout` (входит в резервную копию профиля через префикс `view.`).

```json
{ "version": 1, "order": ["clubs", "insights", "calendar", "editorial"], "hidden": ["calendar"] }
```

- `order` — порядок блоков футбольной главной; `null` означает стандартный порядок текущего оформления (классическое и «Трансляция» имеют разные стандартные порядки).
- `hidden` — скрытые блоки.
- Идентификаторы: `insights` (сводка), `calendar` (экспорт в .ics), `clubs` (ваши клубы), `editorial` (расписание и колонка избранного).
- Неизвестные и повторные идентификаторы отбрасываются; блоки, которых нет в сохранённом порядке, добавляются в конец. Более новые версии читаются по известным полям.
- Повреждённое значение (не JSON-объект или без числового `version` ≥ 1) отклоняется при восстановлении профиля; при чтении в приложении используется стандартное расположение.
- Блоки берут данные из общего `useFootballData` и не создают собственных запросов.

## Режим без спойлеров (v1)

Ключ `sportsdesk.view.spoilers` (входит в резервную копию профиля, проверяется при восстановлении).

```json
{
  "version": 1,
  "items": [
    {
      "kind": "football",
      "id": "<match id>",
      "label": "Арсенал — Челси",
      "eventTime": "2026-11-09T12:00:00Z",
      "addedAt": "2026-11-09T10:00:00Z"
    }
  ]
}
```

- `kind`: `football` или `f1`; пара `kind` + `id` уникальна, дубликаты и битые записи отбрасываются.
- Запись истекает через 7 дней после `eventTime` (или `addedAt`, если времени события нет).
- Скрытые id футбольных матчей передаются в Rust-поллер как `hiddenResults`: для них не создаются уведомления о голах и итогах и записи Центра событий (напоминания «Скоро матч» остаются).
- Маска счёта: `? : ?`. Скрыто в карточках и списках матчей, на главной, в карточке матча (события, статистика, оценки), мини-окне, Центре событий и «Пока вас не было».

## Игры и атмосфера (v1)

Ключ `sportsdesk.view.atmosphere` (входит в резервную копию профиля, проверяется при восстановлении).

```json
{
  "version": 1,
  "enabled": true,
  "celebrations": true,
  "sounds": false,
  "ambient": false,
  "volume": 0.5,
  "motion": "system",
  "ambientKind": "auto",
  "ambientVolume": 0.4,
  "ambientVideo": "stop",
  "ambientHidden": "stop"
}
```

- `enabled` — главный выключатель блока; `celebrations` — конфетти гола и флаг финиша; `sounds` и `ambient` по умолчанию выключены и не включаются сами после обновления.
- `motion`: `system` (как в Windows), `reduced` (без частиц и тряски), `full`.
- `volume` — от 0 до 1, громкость коротких сигналов (рог гола, радио F1); значения вне диапазона обрезаются.
- Поля фонового звука добавлены без смены версии: в старых профилях их нет, при чтении берутся значения по умолчанию, неизвестные значения заменяются ими же, более старое приложение лишние поля игнорирует.
  - `ambient` — разрешает кнопку «Фоновый звук» в верхней панели. Сам фон включается только этой кнопкой (или «Прослушать фон» в настройках) и не запоминается как «играет»: после запуска и обновления он всегда выключен.
  - `ambientKind`: `auto` (стадион в футболе, кубках и ЛЧ, двигатель в Формуле 1), `stadium`, `engine`. При смене вида спорта или значения звук плавно переключается.
  - `ambientVolume` — отдельная громкость фона от 0 до 1 (на слух ограничена запасом 0,5).
  - `ambientVideo`: `stop` — фон выключается, пока видео в «Онлайн-просмотре» звучит (запускать его заново нужно вручную); `lower` — фон тише в 5 раз и возвращается после паузы или выключения звука видео.
  - `ambientHidden`: `stop` — фон выключается, когда окно скрыто в трей или свёрнуто, и сам не возвращается; `keep` — продолжает звучать. Rust присылает событие `sportsdesk://window-visibility`, потому что WebView2 не всегда считает скрытое в трей окно скрытым.
- Фоновые звуки и сигналы синтезируются самим приложением (Web Audio), готовых записей и сторонних файлов нет. Фон не привязан к ходу матча или гонки, поэтому не может раскрыть результат. Тихие часы уведомлений не звучат для автоматических сигналов; фон, включённый вручную, они не прерывают. Сигналы не звучат поверх видео со звуком и из скрытого окна.

Ключ `sportsdesk.view.celebrated` — массив id событий Центра событий, для которых праздник уже показан (не больше 300). Не даёт повторить праздник после перерендера, обновления данных и перезапуска. Празднуются только события `football|goal|…` не старше 10 минут; изменение счёта без события гола (исправление, отмена) не празднуется.

## Командное радио F1

- `sportsdesk.notifications.f1.radio` — `"1"` включает оформление напоминаний о сессиях F1 как радиосообщений SportsDesk (по умолчанию выключено и работает только при включённом блоке «Игры и атмосфера»).
- `sportsdesk.notifications.f1.radioName` — обращение в репликах (до 24 символов, управляющие символы удаляются).
- В Rust уходят поля `f1Radio` и `f1RadioName` конфигурации опроса. Ключ напоминания не меняется, поэтому оформление не создаёт дублей; фильтры и тихие часы применяются как обычно. День недели («гоночная пятница») считается по времени начала сессии в часовом поясе пользователя. Реплики не объявляют пит-стопы и не выдаются за настоящие записи команд.
