# Источники живых футбольных данных для SportsDesk

**Проверено 12 ноября 2026 года (UTC+9).** Для «Сегодня» и «Сейчас идут» я бы взял **API-Football (API-SPORTS), тариф Pro**, если провайдер подтвердит, что можно использовать данные только для личного просмотра в локальном Windows-приложении. У него есть пакетный запрос живых матчей по списку лиг, текущая минута и счёт, а в каталоге есть все нужные турниры, включая шесть зон отбора ЧМ и межконтинентальные стыки. **PitchAPI стоит оставить для составов и статистики.** Если нужно более ясное разрешение на использование данных внутри приложения, следующий кандидат — **Sportmonks**: он дороже, а покрытие некоторых отборов надо подтвердить в кабинете.

**Предел проверки.** Покрытие в каталоге означает, что источник знает турнир. Оно не гарантирует наличие каждого матча, текущей минуты или обновления за 120 секунд. Для ESPN проверил публичные ответы по лигам и датам; для football-data.org — открытый каталог турниров; для TheSportsDB — бесплатный запрос расписания и официальный пример платного live-ответа. Остальные запросы описаны по документации. Подписки не покупал, запросы с личными ключами не выполнял. Задержку от события на поле до экрана ни для одного источника не измерял.

## 3. Как опрашивать экономно

1. **Собрать «Сегодня» отдельным запросом расписания.** Местные сутки **12.11.2026** — это интервал UTC **[11.11 15:00, 12.11 15:00)**. Для API-Football начать с одного запроса `/fixtures?date=2026-11-12&timezone=Asia%2FYakutsk`, отфильтровать лиги по ID и перепроверить границы по `fixture.timestamp`. Допустимость точного значения `Asia/Yakutsk` проверить через `https://v3.football.api-sports.io/timezone`, а выборку даты — на играх по обе стороны полуночи: с ключом это **не проверено**. Если границы не совпадут, брать две UTC-даты отдельными запросами и обрезать по интервалу. Для football-data.org это один диапазон UTC с исключающей правой датой, для PitchAPI — два запроса по UTC-датам. Для TheSportsDB — до двух запросов на лигу через `eventsday.php`, затем фильтр по времени старта; для MLS и пограничных матчей проверить семантику даты на примерах.
2. **Опрос по минуте только возле матчей.** Загружать расписание при запуске, после выхода из сна, при смене местной даты и примерно раз в час, пока приложение открыто. Включать live за 5–10 минут до ближайшего старта. В `live=…` передавать одним списком ID лиг с матчами, которые скоро начнутся или ещё не завершились. Добавлять ID по мере приближения следующих игр; проверять состав ответа и ошибки даже при HTTP 200. Если API-Football не вернул матч, это не означает, что матч завершён: подтвердить финальный статус через `/fixtures?ids=…` (до 20 ID в запросе) или сверить расписание. При паузах, переносах и пропавшем сигнале сохранить последнее состояние и время его получения. «Сейчас идут» как фильтр «Сегодня» применяет те же границы даты старта; если нужен отдельный режим *все идущие*, в нём оставить и матчи, начавшиеся вчера.
3. **Бюджет запросов.** Без матчей — **0 live-запросов/ч** плюс примерно **1 запрос расписания/ч** (или 2 при запросах по UTC-дням). При матчах — **60 live-запросов/ч** суммарно на все активные лиги, плюс **1–2** на расписание и редкие запросы для сверки финалов. Два активных часа в одном окне квоты уже дают **120 live-запросов**, сверх Free 100/сутки. Три часа дают около **184 запросов** при одном запросе расписания в час и одной сверке финалов. Даже непрерывный live-опрос 24 часа составит **1 440** запросов до сверок, ниже 7 500/сутки Pro. Если запасной источник требует запрос по каждому турниру и дате, три активные пары «лига–дата» стоят **180/ч**, шесть — **360/ч**.
4. **Прежде чем менять основной источник, проверить его на игровом дне.** На Free можно проверить ключ, форму ответа, часовой пояс и несколько коротких live-окон, если текущий сезон доступен. Полный день с минутным опросом лучше проверить на Pro. Сверить состав матчей с официальными календарями лиг, отдельно взять MLS, Лигу конференций и доступный отбор; проверить старт, гол, перерыв, финал, дополнительное время и матчи на границе UTC+9. Замерять задержку до первого появления изменения в приложении и число пропусков. Минутный опрос сам добавляет до **60 с**; для цели **≤120 с** у всей цепочки поставки и сети остаётся около минуты. Если это жёсткое требование, ни один проверенный публичный тариф его документально не гарантирует.

Для SportsDesk имеет смысл сделать API-Football основным источником **одновременно для списка «Сегодня» и его live-состояния**: один `fixture.id` связывает расписание, текущий счёт и финал. Связывать с PitchAPI нужно только для перехода к деталям. Ключ вводится пользователем и хранится локально под Windows DPAPI; запросы идут из Rust. При `429`, потере сети или исчерпании квоты показывать последний полученный счёт с отметкой времени, а отсутствующую минуту — пустой. Это позволит убрать зависимость списка «Сегодня» от ограничения SportScore на первые 50 матчей суток.
